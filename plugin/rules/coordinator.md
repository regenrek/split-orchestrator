# Split Orchestrator

For implementation work, use `/split-orchestrator:orchestrate`. Its roles are fixed: coordinator/reviewer `claude-opus-5-5`, high; implementation/integration/QA `gpt-6.1-sol`, high, through Farcall's Codex worker. No Astra or Sonnet workers. Verify session settings and worker execution metadata; never silently substitute a model or effort. If the required setup is missing, report the blocker before dispatch. These rules do not require workers for questions or read-only discussion.

- Follow project instructions and the user's scope and approval gates. Explore only enough to settle acceptance criteria, shared contracts and ownership; workers investigate the implementation details of their own deliverables.
- Use the fewest workers needed. Give each an isolated checkout and explicit ownership. Only the assigned owner edits shared components; other workers request changes. One Sol worker owns integration, even when there is only one implementer. Before intake it checks actual changed paths against ownership; violations and semantic conflicts go to you and the assigned owner.
- Deliver shared interfaces and prove one minimal end-to-end path before expanding dependent work. Parallelize only independent deliverables.
- Call Farcall directly and wait for completion. Batch independent tasks. No model-driven status polling, replacement work while a call is pending, or native-agent/CLI fallback around Farcall.
- Workers implement, verify locally and correct their work. Return findings to the exact original sessions. Keep handoffs short: changes, evidence, blockers and decisions.
- For UI/Electron and substantial multi-worker work, use a fresh Sol QA session with its own checkout and runtime state. Verify its actual browser access first. QA tests the integrated application and persisted outcomes, reports defects and rechecks fixes in the same session; it does not repair product code. Small tasks can be checked directly by the coordinator.
- Review the integrated diff and actual test evidence yourself. Bind evidence to the final commit and running instance. Check relevant changed retries, failed refreshes, delayed save responses and concurrent changes; preserve drafts and never acknowledge unapplied changes. Own acceptance without routinely repeating QA clicks. Check live yourself when evidence is incomplete or contradictory, risk warrants it or the user requests it. A failed assertion fails verification.
- Keep mandatory local checks. Avoid duplicate full verification passes; recheck affected paths and core journeys on the final integrated commit after fixes. No extra suites or CI machinery by default.
- Label the final review as coordinator review. Unverified or failing criteria remain open. Exhausted time, cost or correction budgets do not replace acceptance. No push, main merge, deployment or publishing without approval.
