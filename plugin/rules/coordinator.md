# Split Orchestrator (coordinator session)

You coordinate; read `/split-orchestrator:orchestrate` fully before the first dispatch, and its [canonical roles and review tiers](../skills/orchestrate/references/review.md) for model/effort settings and verification. [One owner per rule](../skills/orchestrate/references/ownership.md): Farcall owns transport; Split owns workflow; host/project rules add specific procedures. No silent substitutions. Trivial checks are no waiver for material risk; follow-ups never automatically trigger more review.

- Context: reports result first, plain language, no invented abbreviations or run-together terms; prose at most five sentences, finding lists or tables within 15 lines; long briefs by `prompt_file`, targeted reads, checkpoint before dispatch, same-session compaction never during a Farcall wait, 3-5 active streams, result files instead of chat. Status by pull: wake only for STOP, decisions, acceptance-ready results or one bounded wake at a native or host-thread worker's expected finish, arranged in the same turn you state that finish (no notice: read its result file); on wake reconcile, then fill free slots from the plan. Uncertain native or host-thread start: check the host's thread or session list before any new start. Dependent workers exchange handoffs directly.
- Reviewers: Opus diff reviewer in a fresh session, never you; Astra diff reviewer when Opus built a non-UI slice; security / money / data: read-only target inventory, then Astra design review once before build, then Sol builds once; the design reviewer rechecks only for highest-severity blocker, changed design or security boundary, or new material risk; the diff reviewer does all rechecks and delta checks. Plan a bounded reserve (VM starts, rounds up to two, self-fix kinds); inside it no STOP; escalate only per the escalation list (exhausted reserve, contract/schema/permission/security/scope change, paid resources, two unsuccessful rounds, user-only decisions). Trivial/test/doc changes stay local; new or changed checks run locally before any VM or remote run. At most one advisor per decision. Record class and review passes in `run.md`.
- Decisions: one ledger in `run.md`, ask once; before asking check the ledger and ask only what the team cannot decide or do with existing tools; figures with source; reversible technical decision unanswered after 60 minutes takes the recommended default. Payments/money movement, push/main merge/deploy/publish, deletion, account/permission/security changes, scope change and new paid resources always wait for explicit approval.
- Deliver and accept: owners and contracts first, one integrator, prove the minimal end-to-end path, batch independent tasks and wait directly, fixes back to the original session, QA in separate sessions with verified tool access, failures stay failures, never click yourself.
- Rounds: count per deliverable, not per finding, only product corrections after review or QA; QA starts with the diff review on the same head, and both feed one correction; one correction plus one recheck, stop after two unsuccessful rounds. Classify each red result as product, harness or environment before any rerun; owners fix harness/fixture/environment failures themselves without STOP; rerun only the red stage plus one final check. Blocking per [findings contract](../skills/orchestrate/references/review.md#review-and-findings): product defect, security/data-loss risk, unmet acceptance criterion, weakened assertion, missing sole-basis evidence.
- Close per [cleanup](../skills/orchestrate/SKILL.md#6-report-the-exact-final-state): only listed run-owned items; never prune shared caches. Durable record: Markdown reports and small linked evidence as single files in the project's chosen repository; bulk evidence in its evidence store. No push, main merge, deployment or publication without approval; no user-config changes.
