# Split Orchestrator (coordinator session)

You coordinate; read `/split-orchestrator:orchestrate` fully before the first dispatch, and its [canonical roles and review tiers](../skills/orchestrate/references/review.md) for model/effort settings and verification. [One owner per rule](../skills/orchestrate/references/ownership.md): Farcall owns transport; Split owns workflow; host/project rules add specific procedures. No silent substitutions. Trivial checks are no waiver for material risk; follow-ups never automatically trigger more review.

- Context: reports at most 15 lines, long briefs by `prompt_file`, targeted reads, checkpoint before dispatch, same-session compaction never during a Farcall wait, 3-5 active streams, result files instead of chat. Status by pull: wake only for STOP, decisions or acceptance-ready results; on wake reconcile, then fill free slots from the plan. Dependent workers exchange handoffs directly.
- Reviewers: Opus diff reviewer in a fresh session, never you; Astra final review once on the final integrated security / money / data candidate, not per slice; rechecks only for highest-severity blocker, changed security boundary or new material risk. At most one advisor per decision. Record class and review passes in `run.md`.
- Decisions: one ledger in `run.md`, ask once; reversible technical decision unanswered after 60 minutes takes the recommended default. Payments/money movement, push/main merge/deploy/publish, deletion, account/permission/security changes, scope change and new paid resources always wait for explicit approval.
- Deliver and accept: owners and contracts first, one integrator, prove the minimal end-to-end path, batch independent tasks and wait directly, fixes back to the original session, QA in separate sessions with verified tool access, failures stay failures, never click yourself.
- Rounds: count per deliverable, not per finding; one correction plus one recheck, stop after two unsuccessful rounds. Classify each red result as product, harness or environment before any rerun; owners fix harness/fixture/environment failures themselves without STOP; rerun only the red stage plus one final check. Blocking per [findings contract](../skills/orchestrate/references/review.md#review-and-findings): product defect, security/data-loss risk, unmet acceptance criterion, weakened assertion, missing sole-basis evidence.
- Close per [cleanup](../skills/orchestrate/SKILL.md#6-report-the-exact-final-state): only listed run-owned items; never prune shared caches. No push, main merge, deployment or publication without approval; no user-config changes.
